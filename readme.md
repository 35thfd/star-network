# 卫星网络模拟项目

## 项目概述

本项目旨在模拟一个包含基站和多个卫星的通信网络。其核心目标是研究在动态网络拓扑下，卫星节点间高效的数据分发策略。模拟中，卫星节点致力于收全最初由基站持有的数据分片。它们可以通过与邻近卫星交换数据或直接向基站请求来获取所需分片。

为构建逼真的模拟环境，本项目采用 Docker 技术，为每个网络节点（卫星或基站）创建隔离的运行容器。通过 `tc` (traffic control) 工具动态调整容器间的网络链路状态，以模拟卫星网络中链路可能发生的变化。

项目中的关键技术点包括：卫星节点的邻居发现机制、数据分片缺失信息的交换、以及旨在提升数据收集效率的智能数据交换优先级算法。

## 主要功能

* **基于 Docker 的模拟环境**: 每个卫星和基站都在独立的 Docker 容器中运行。
* **动态网络拓扑**: `run_simulation.sh` 脚本会周期性地使用 `tc` 工具修改卫星间的网络连接，以模拟链路变化。
* **节点类型**:
    * **基站 (`sta_main.cpp`)**: 作为所有数据分片的初始持有者，并响应卫星的请求。
    * **卫星 (`satellite.cpp`)**: 网络中的主要数据交换和处理节点。功能包括：
        * 通过心跳消息发现邻居卫星。
        * 交换缺失数据分片列表。
        * 请求和发送特定的数据分片。
        * 基于“频次”算法（即某一分片被其邻居节点共同缺失的程度）来确定请求或发送数据分片的优先级。
        * 维护稳定邻居列表并适应网络变化。
* **基于 UDP 的消息通信**: 定义了多种消息类型用于节点间交互：
    * **Type 0**: 数据包，包含具体的数据分片。
    * **Type 1**: 卫星发送的控制消息，通常包含其（经过优先级排序的）缺失数据分片列表。
    * **Type 2**: 由基站发送，例如，告知卫星数据分片的总数量。
    * **Type 3**: 心跳或广播消息，用于卫星进行邻居发现。
* **数据分片优先级策略**: 卫星节点会统计自身及其邻居对各数据分片的缺失情况，计算“频次”，从而优先处理那些“需求量大”的分片。
* **邻居管理**: 卫星节点能够发现并维护一个邻居列表，跟踪邻居节点的稳定性，并处理超时断连等情况。

## 如何配置和运行

**主要运行方式**:

使用 `network/run_simulation.sh` 脚本来启动完整的动态模拟。

1.  **环境准备**:
    * 确保你已经安装并运行了 Docker。
    * 你的操作系统需要支持 Bash 脚本的执行。
    * 如果你使用的是 macOS，`run_simulation.sh` 脚本会使用 `osascript` 命令为每个 Docker 容器打开一个新的终端窗口来显示其输出。如果不是 macOS，你可能需要修改这部分脚本，或者通过 `docker logs -f <container_name>` 手动查看容器日志。

2.  **进入`network`目录**:
    打开终端，并切换到包含所有相关文件的 `network` 目录。例如：
    ```bash
    cd path/to/your/project/network
    ```

3.  **赋予脚本执行权限** (如果尚未设置):
    ```bash
    chmod +x run_simulation.sh
    chmod +x control_tc.sh # 这个脚本会被 run_simulation.sh 调用
    ```

4.  **执行模拟脚本**:
    ```bash
    ./run_simulation.sh
    ```

**`run_simulation.sh` 脚本会执行以下操作**:
* **构建 Docker 镜像**:
    * 为卫星节点构建名为 `satellite-image` 的 Docker 镜像 (基于 `Dockerfile.satellite`)。
    * 为基站节点构建名为 `sta-main-image` 的 Docker 镜像 (基于 `Dockerfile.sta_main`)。
* **网络和容器管理**:
    * 如果之前有同名容器（如 `station`, `sat1`, `sat2` 等），会先删除它们。
    * 创建一个名为 `my_network` 的 Docker 自定义桥接网络（如果它还不存在）。
    * 启动一个名为 `station` 的基站容器。
    * 启动多个卫星容器（默认为10个，名为 `sat1` 到 `sat10`）。
* **显示输出**:
    * 在 macOS 上，会为每个容器打开一个新的终端窗口显示其实时日志。
* **动态拓扑模拟**:
    * 脚本会进入一个循环，定期随机选择容器对，并使用 `control_tc.sh` 脚本在源容器内部执行 `tc` (traffic control) 命令，来模拟连接的建立或断开 (通过允许或丢弃目标 IP 的数据包)。

**其他运行脚本**:

项目根目录中还存在其他可以用于启动容器的脚本，它们提供了略微不同的配置或启动方式：

* **`network/build.sh`**:
    * 构建 `satellite-image` 和 `sta-main-image`。
    * 启动名为 `satellitea`, `satelliteb`, `satellitec` 的三个卫星容器和名为 `sta_main` 的一个基站容器。
    * 它们会被连接到 `my_network` 这个 Docker 网络。
    * 同样，在 macOS 上会为每个容器打开新终端窗口。
* **`network/run.sh`**:
    * 创建一个名为 `my_network` 的 Docker 网络，并指定子网 `192.168.1.0/24`。
    * 启动一个名为 `basestation` 的基站容器，并指定其 IP 为 `192.168.1.100`。
    * 启动五个名为 `satellite1` 到 `satellite5` 的卫星容器，并分别指定它们的 IP 从 `192.168.1.101` 到 `192.168.1.105`。
